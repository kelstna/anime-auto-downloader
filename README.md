## 一、快速开始

### 1. 首次使用

```
双击 start.bat
```

浏览器会自动打开 `http://127.0.0.1:7788`。若没自动打开，手动访问即可。

> 想看到日志窗口就用 `start-debug.bat`；想结束进程用 `stop.bat`。

### 2. 填写 Bangumi Token

1. 打开页面左侧「在看番剧」页
2. 点击 **获取 Token ↗**（跳转 <https://next.bgm.tv/demo/access-token>）复制令牌
3. 粘贴到 Token 输入框 → 点「保存并验证」
4. 点「拉取在看番剧」，看到番剧卡片（封面 + 名称）即成功

### 3. 选番剧 → 选字幕组 → 加入订阅

1. 点击任意番剧卡片，弹出资源窗口
2. 切到「订阅设置」标签页，**在这一页就能全部搞定**：
   - **限定字幕组**：下拉选择（选项来自各站真实搜索结果，含「N 条 · 来源站点」），选定后只从这个组下载
  —— **自动追番时也严格按这个组过滤**：站点搜索是模糊匹配（用「[ANi] 番名」去 Nyaa 搜照样会带回
  别的组），所以候选资源还会再用组名核对一次，不是该组的直接丢弃（回归：`tests/test_engine.py`
  的 `test_group_filter_only_keeps_chosen_group`）。组名匹配容忍繁简与「字幕组」后缀差异，
  但**不做 ASCII 短名前缀匹配**（`ANi` 与 `AnoZu` 曾被判成同一个组）
   - **限定分辨率 / 立即下载哪一集**：集数下拉会按所选字幕组与分辨率自动挑出每集最优的一条，
     显示成「第 13 集 · 桜都字幕组 · 1080p · 384.2MB」；默认「不下载」= 只订阅、之后自动追新
   - **下载目录 / 以后新集怎么下 / 总话数**
   - 下方预览行会实时告诉你「将订阅：番剧名 · 字幕组 · 分辨率 · 立即下载第 N 集 · 目录」
3. 点「加入订阅」即完成订阅（选了几集就同时推送下载）
4. 想挑别的版本（简体内嵌 / 简繁内封 / 合集）时，点「去资源列表挑选单集 / 合集」切到资源列表，
   可继续按 **资源站、字幕组、字幕语言、分辨率、排序、合集/噪声开关** 筛选，行内「下载」直接推送该条资源
5. **自动搜索搜不到、或想指定某个写法**时，用资源列表顶部的 **手动搜索**：
   - 输入关键词（可带字幕组名，例如 `ANi 药屋少女的呢喃`）→ 回车或点「手动搜索」，
     **只按这个词搜**（不再展开番剧别名），并按「站点 → 字幕组 → 语言 → 分辨率」继续筛选
   - 加订阅时这个词会**存进订阅**（资源列表「加入订阅」和「订阅设置 → 自定义搜索词」都会带上它），
     之后**自动追新也只用这个词**；点「恢复自动搜索」清空即可回到按番剧名/别名搜索
   - 手动搜索有独立的缓存口径（不同关键词互不串味），换词会重新联网搜一次

之后这部番就会**自动追新**：后台每隔 N 分钟用「字幕组 + 番剧名」（手册里填了自定义搜索词就用那个词）搜索，
发现比已下载集数更新的剧集就自动加进 qBittorrent。

### 4. 批量订阅（首页的勾选框 / 全选）

在「在看番剧」页勾选多部番剧后，工具栏会出现批量操作：

| 按钮 | 作用 |
|---|---|
| 批量订阅选中番剧 | 按默认设置给每部建订阅，之后由后台自动追番下载 |
| 只拉取信息，不下载 | 只建订阅（`initial_mode=none`），把当前进度记为基线，只追以后的新集 |
| 清空选择 | 取消全部勾选 |

### 5. 事后补下载某一集

在「我的订阅」页，每个订阅都有 **补下载单集** 按钮：点开即搜索该番资源，
选中某条后直接推送到 qBittorrent —— 用来补之前漏掉的某一集或整季合集，不用回首页。

### 搜索耗时与缓存（弹窗为什么有时很快、有时要等）

弹窗里的资源列表和「补下载单集」都走 `/api/search`，逻辑是**先看缓存、没有才联网**：

| 情况 | 表现 |
| --- | --- |
| 预热过（后台每半小时会预热在看番剧） | **0.01 秒**返回，筛选在本地做（缓存里存的是全量资源） |
| 缓存键带了字幕组 / 语言 / 手动关键词 | 先精确查，查不到就回退到该番剧的默认缓存，仍然 0.01 秒 |
| 真的一條缓存都没有（新订阅 / 刚启动 / 手动「重新搜索」） | 联网并发搜 3 个站点，正常 3~10 秒 |
| 某个站点抽风（例如动漫花园返回 HTTP 500） | 该站点**一次就停**（不再拿剩下关键词反复打），单站总预算 45 秒；这次结果会少一个站 |

所以「有时候转圈很久」通常只有两种原因：**冷缓存下的首次搜索**，或**某个资源站当时在报错/超时**。
界面上「用时 x.xxs · 来自缓存 · 命中 N 条 · 各站结果」那行就是给这件事看的。

### 搜索关键词规则（改 `bangumi.build_aliases` / `util.clean_keyword` 前先看这里）

站内搜索基本都是「标题 LIKE %关键词%」，关键词写错一个字就少一堆结果。规则是实测出来的：

| 规则 | 例子 | 为什么 |
|---|---|---|
| 中日文标点换成空格 | `野生的大魔王出现了！第二季` → `野生的大魔王出现了` | 标题里常写成「出现了！ 第二季」（带空格），带「！」的关键词一条都匹配不上：**2 条 → 11 条** |
| 去掉「第几季」 | `间谍过家家 第三季` → `间谍过家家`；`Season 3` / `S03` 同理 | 带上季数会漏掉同名的其它季与合集 |
| **英文那组用罗马音**（不是英文名） | `The Apothecary Diaries` → `Kusuriya no Hitorigoto`；`Seitokai ni mo Ana wa Aru`；`Zombie Sagashitemasu` | 用户要求「英文名搜索改成罗马音搜索」：中文字幕组的标题里几乎都带罗马音（`… / Kusuriya no Hitorigoto [49]`），而**英文名只会搜到欧美压制组**（ToonsHub 那种），一长串英文句子（`There is also a hole in the student organization!`）更是一条都搜不到 |
| 罗马音从哪来 | ① Bangumi 别名/罗马字字段里「像罗马音」的（含日语助词 no/ga/ni/wa、或日语特有音节 shi/tsu/kya…）② 日文原名（纯假名，或片假名外来语查表）转写 ③ 假名标题去掉 `#★♪` 这类装饰符再转 | 汉字读音没有词典转不了，所以优先用 Bangumi 已经给好的罗马字；`FX Senshi Kurumi-chan`（真罗马音）会排在 `FX Fighter Kurumi-chan`（英文别名）前面 |
| 英文名留作兜底 | 罗马音之后才是短英文名（≤4 个词、≤42 字符） | 罗马音搜不到时（部分站点只有英文标题）还能兜住；长句子别名直接丢掉 |
| 英文关键词**也去掉标点** | `STEEL BALL RUN JoJo's Bizarre Adventure` → `STEEL BALL RUN JoJo s Bizarre Adventure`（原样写法作为后面的兜底关键词保留） | 用户要求；中文关键词里 ASCII 标点仍保留（`FX Senshi Kurumi-chan` 去掉连字符反而搜不到） |
| 三种语言每种都真搜一次 | 简体 → 繁体 → 罗马音/英文交错排列，`wanted_groups` 里的语言没搜全就不收手 | 用户要求「三种搜索词的结果都显示」，不能因为简体先搜到就跳过繁体/英文 |
| **不用日文原名** | `FX戦士くるみちゃん` 不参与搜索 | 含假名的日文名在三个站点基本搜不到；日文原名只用来生成罗马字 |
| 关键词逐个补搜 | 三种语言都搜过、且条数够了（默认 ≥5）才停 | 以前「第一个关键词有结果就停」，换个写法能搜到的资源全漏了 |
| **每个名字都要轮到一次** | 候选按「清洗级别」分层展开：先各名字的清洗版，再各名字的激进版，最后原样兜底 | 以前一个名字一口气展开 3 个变体，前两个名字就吃掉 6 个槽位，第 3 个名字永远搜不到 |
| 简/繁名相同时不重复搜 | 繁体名跟简体名一字不差（没用到繁体字）时直接去重 | 省下来的预算留给真正不同的名字 |
| 关键词预算 10（`search.max_keyword_variants`） | 结果不够就继续换写法；凑够 5 条立刻收手 | 实测有番剧正确罗马字排在第 5 位，旧预算 4 直接把它截掉了 |
| **记住哪个关键词真管用** | `data/keyword_stats.json` 记录每个关键词在每站的命中数，下次排到候选表最前，并进缓存键 | 规则猜不准哪个写法有用，实测一次就学会了 —— 详见下面「关键词是怎么选出来、又怎么记住的」 |

### 关键词是怎么选出来、又怎么记住的

用户实测：**「黑暗召唤师在地下恋爱中」只搜到 1 条**。Bangumi 给的 6 个名字里，
`Dark Samon atodekiteiru`（机器生拼）和 `Dark Summoner to Dekiteiru`（人工修正的真罗马字）
长得都像罗马字，而管用的那个排在候选表第 5 位，被「每站只试 4 个关键词」的上限截断了。

**光靠规则猜哪个写法对是猜不准的**，所以改成「规则排序 + 多试几个 + 记住实测结果」三层：

| 层 | 做法 |
|---|---|
| ① 排序 | `looks_like_romaji()`：**独立成词的日语助词**（to/no/ga/ni/wa/kara/chan…）或日语特有音节（shi/tsu/kya…）才算罗马字 —— `Dark Summoner to Dekiteiru` 里 `to` 独立成词 ✓，`Dark Samon atodekiteiru` 把 `to` 吞进 `atode…` ✗，于是真罗马字排到英文组第一 |
| ② 预算 | 每站最多试 10 个写法（配置 v3 自动把旧的 4 迁移成 10）；候选**分层展开**保证每个不同名字都轮到一次；凑够 5 条就早停，热门番仍然只打 3~4 次请求 |
| ③ 学习 | `core/keywords.py` 把「站点 + 关键词 + 命中条数」记进 `data/keyword_stats.json`；下次搜同一部番时**搜到过资源的关键词排最前**（按命中数从高到低）。学习结果的变化会写进搜索缓存键（`…\|lk=<指纹>`），旧缓存自动失效，重搜一次后就稳定命中缓存 |

现场实测（subject 630160）：

```
修复前：命中 1 条    只用到 黑暗召唤师在地下恋爱中 / 黑暗召唤师在地下戀愛中 / Dark Samon atodekiteiru / Dark Samonatodekiteiru
修复后：命中 21 条   kisssub → Dark Summoner to Dekiteiru / nyaa → Dark Summoner to Dekiteiru / dmhy → Dark Summoner to Dekiteiru …
学习记录：{"Dark Summoner to Dekiteiru": 20 条（dmhy 2 + nyaa 18），"黑暗召唤师在地下恋爱中": 1 条}
第二次搜索：这条关键词已是各站第一位；第三次搜索直接命中缓存
```

季数不再进关键词之后，**必须自己认季**：搜索关键词不带季数，结果里会混进同一系列其它季的资源
（用户实测：订阅进度出现「49 / 12 集」）。处理分三层：
1. `api_search` 直接**不返回**其它季的资源（`util.in_current_season`），弹窗里写明「已隐藏 N 条其它季资源」；
2. `watcher._new_candidates()` 同样只认本季（明确写着别的季、或集号早于本季起点的一律排除）；
3. 订阅里记的集号统一换算成本季编号（`_probe/fix_episode_numbers.py --apply` 可一次性修正老数据）。

### 集数识别与「系列连续编号」换算

| 场景 | 处理 |
|---|---|
| `[ANi] Season 2 - 171 …` | 季数标记里的数字**不是**集号（踩过：被识别成第 2 集），按 `- 171` 取 171 |
| `[SubsPlease] … - 171 (480p) [E6AB6CBC].mkv` | 种子名里的 `E6AB6CBC` 不是集号（踩过：被识别成第 6 集） |
| `S02E05` / `第2季 第5话` / `[02]` / `[01-12]` | 正常解析（季数标记先抹掉再解析，`S02E05` 不受影响） |
| 发布组沿用**系列连续编号** | 药屋第三季（12 话）标题里是 49~60 → 界面按本季显示 **1~12**（`episode_offset`）；黑色五叶草第二季是 171 → 第 1 集；大魔王第二季是 13/14 → 第 1/2 集 |
| **手动下载也换算集号** | 资源列表里的「下载」/「补下载单集」以前记的是**标题原始编号**（药屋第三季记成 50、冰之城墙第二季记成 15），进度会出现「50 / 12 集」；现在统一按订阅的偏移量换算成本季集号，历史里另存 `episode_absolute` |
| 进度自愈 | 每次检查订阅时，若 `last_episode` 大于总话数（老数据 / 偏移量随可见资源漂移），用「当前偏移量或订阅里存过的偏移量」换算回 1..总话数（`watcher._normalize_last_episode`） |

本季起点由 `util.resolve_episode_offset()` 判断，三条规则按可靠程度依次尝试，都判不出来就**不换算**（也就不用季过滤，宁可不筛）：

1. **发布时间**（最可靠）：本季开播（Bangumi `date`）前 7 天之后发布的资源才是本季的。
   药屋第三季开播 2026-10-02，49~ 才是本季；大魔王第二季电视开播 10-03，但先行配信的 13（=本季第 1 集）09-27 就发了，所以放宽一周。
2. **标题里的季数标记**：黑色五叶草第二季的结果混着第 1 季（20/40/72…）和本季（171…），只有带「Season 2 / 2nd Season」的那批属于本季。
3. **超过本季话数的集号是否连续**：只有一批连续编号时的兜底判断（跨度超过本季长度就放弃）。

换算只在**显示与订阅记账**层：`/api/search` 返回 `episode`（本季编号）+ `episode_absolute`（标题里的编号，鼠标停在「集数」上能看到）；
`watcher` 记账时同样换算成本季编号，所以订阅卡片显示的是「第 2 / 12 集」而不是「14 / 12 集」。

### 局域网访问（手机 / 平板 / 另一台电脑）

1. 「设置 → 服务」把 **允许局域网访问** 打开（等价于 `data/config.json` 里 `"server": {"host": "0.0.0.0", "allow_lan": true}`），保存。
2. **重启服务**（关掉后重新双击 `start.bat`；`allow_lan` 这类监听项只有重启才重新绑定）。
3. 重启后「设置 → 服务」里会直接列出可用地址，例如：

   ```
   局域网地址（同一 Wi-Fi 下用手机/平板打开）： http://192.168.1.100:7788/
   （如果打不开，检查 Windows 防火墙是否放行、或这台电脑的 IP 是否变了）
   ```

   启动日志里也会打印同样的列表。地址来源是 `util.lan_ipv4_addresses()`：拿本机所有 IPv4，
   过滤掉别人访问不到的回环（`127.*`）、链路本地（`169.254.*`）和代理软件的 fake-IP 段（`198.18/15`），
   再按 `192.168.*` → `10.*` → `172.16~31.*` → 其它排序，家用网最常见的排最前。
4. 连不上时按顺序查：
   - 手机和电脑是不是**同一个** Wi-Fi / 网段（公司网、访客网常常互相隔离）；
   - Windows 防火墙：本机 `netsh advfirewall show allprofiles state`，公网配置文件关着就不会挡；
     开着的话需要放行 TCP 7788（`netsh advfirewall firewall add rule name="自动下载番剧 7788" dir=in action=allow protocol=TCP localport=7788`，要管理员）；
   - 电脑的 IP 变了（DHCP）——换成设置页刷新出来的新地址。

> ⚠️ 这个页面**没有密码**：同一局域网里的任何设备打开它都能加订阅、删任务、删本地文件，也能在设置页看到 Bangumi Token。
> 只在信任的家庭网络里开；如果想更保险，说一声，我可以加一个访问密码（打开页面先输一次，之后记住）。

### 更新时刻（北京时间，精确到分钟）

**Bangumi 官方接口给不了"几点几分"**：`/v0/subjects/{id}` 只有 `date`（首播日期）与 infobox 里的
「放送星期 / 播放电视台」，`/v0/episodes` 的 `airdate` 也只有 `YYYY-MM-DD`（实测见 `_probe/t_airtime.py`）。

所以用社区维护的 **bangumi-data**（npm 包 `dist/data.json`，约 8900 条 / 7.5 MB）：

| 字段 | 用途 |
|---|---|
| `begin` | 放送时刻（UTC ISO，精确到分钟）→ **+8 小时 = 北京时间** |
| `broadcast` | RFC5545 重复区间（`R/2026-10-04T16:20:00.000Z/P7D` = 每周一集）→ 往后推算出「下一次」 |
| `sites` | 各站 ID 映射（bangumi / aniList / mal …），AniList 的 `airingAt` 时间戳可作独立交叉验证 |

落地方式（`app/core/airtimes.py`）：

1. 下载整份数据 → 压成精简索引（只留 begin/end/周期/站点映射）→ 存 `data/airtimes.json`（约 1.9 MB / 8840 部番）
2. **每天刷新一次**（`airtime.refresh_hours`，默认 24）：服务启动时后台刷、之后任何一次查询发现过期也后台刷；
   **永远不阻塞请求**，下载失败就继续用旧数据（新番收录本来就滞后，宁可用旧数据也别报错）
3. 接口把 `airtime` 挂在 `/api/bangumi/collections` 与 `/api/subscriptions` 上；
   **电视台**取自 Bangumi infobox 的「播放电视台」（bangumi-data 里没这个字段，没收录就写「Bangumi 未收录」）

**「已完结」怎么判**（用户要求：完结的番别显示编造的更新时间）：

| 判据 | 说明 |
|---|---|
| ① bangumi-data 的 `end` | 有值且已经过去 → 已完结 |
| ② 首播 + 周期 × 总话数 | 最后一集 = 首播 + 周期×(总话数−1)，再宽限 1 天 → 之后算已完结（总话数取自 Bangumi） |
| ③ 判不出来就不判 | 没有 `end`、又不知道总话数时，照常显示下一次更新（宁可不判也不误报） |

实测：你「在看」里 35 部 → 15 部在播（显示下次更新）+ 20 部已完结（显示「已完结」+ 最后一集时间）。
列表页「只看在播/未完结」默认**不勾选**，所以 35 部全都在页面上；勾上才会把已完结的藏起来。

实测（北京时间）：

| 番剧 | 首播 | 下次更新 | 日本时间 |
|---|---|---|---|
| 药屋少女的呢喃 第三季 | 10-02 22:00 周五 | 10-16 22:00 | 10-16 23:00 |
| 黑暗召唤师在地下恋爱中 | 10-05 00:20 周一 | 10-12 00:20（AniList 同） | 10-12 01:20 |
| 转生就是剑 第二季 | 10-07 23:00 周三 | 10-14 23:00 | 10-15 00:00 |

> ⚠️ 这是**日本电视台播出时刻**，不是资源出现时刻：字幕组通常晚 10 分钟 ~ 几小时（有的隔天）。
> 想让"出了就下"更及时，可以在播出时刻后加密检查（本次没有改追番节奏，只做了展示）。

### 缓存与自动更新是怎么工作的

```
第一次拉取在看（约 9 秒，36 部）
   └─ 顺带后台预热：逐部搜索三站资源并落盘（进度显示在 Token 面板下方）
再次拉取在看
   └─ 15 分钟内：直接读缓存（0.0 秒）
   └─ 超过 15 分钟：先用旧数据显示，同时后台线程去 Bangumi 拉最新并写回
点开某部番剧
   └─ 命中预热缓存：0.01 秒显示（搜索状态处标注「来自缓存 · N 分钟前」）
   └─ 点「重新搜索」：强制重新联网（约 4~26 秒，取决于站点响应）
换 token 时
   └─ 缓存键包含 token 指纹，自动失效，不会把上一个号的数据当自己的
```

设置页有「资源缓存」面板：可立即预热全部番剧、停止预热、清理 `search:` 前缀缓存。
相关配置在 `data/config.json` 的 `cache` 段（`collections_ttl_minutes` / `search_ttl_minutes` /
`auto_search_on_fetch` / `auto_search_concurrency`）。

### 加入订阅时的「首次下载」策略

| 取值 | 行为 |
|---|---|

## 七、后台占用优化

- 整个服务是**单进程 + 少量短生命周期线程**：Web 服务线程按需创建，追番检查每个站点并发 1 个请求
- 空闲时后台线程每 30 秒才醒一次做时间判断，不做任何网络请求
- 追番检查默认 30 分钟一轮，只对**已订阅**的番剧发请求；每个站点每部番最多 3~4 个关键词
- 封面图代理后落盘缓存（`data/covers/`），浏览器不再重复联网
- 日志自动滚动，单个文件上限 2 MB，最多保留 3 个备份
- **不代理 qBittorrent**，也不参与它的任何下载流量

## 八、常见问题

**qBittorrent 连不上**
检查设置页的 WebUI 地址与端口是否与 qBittorrent「选项 → WebUI」一致；点「测试连接」看具体错误。
本机访问通常免密；如果开启了「对本地主机跳过身份验证」的反向设置，请在设置页填用户名密码。

**爱恋动漫搜不到**
该站有「访客验证」反爬页，程序会自动完成一次验证并复用 Cookie。若偶发失败，等下一次检查即可（会自动重试）。

**Nyaa 搜不到中文名**
Nyaa 以罗马字/英文标题为主，程序会优先用英文名与假名转罗马字搜索；如果这部番在 Nyaa 上确实没有资源，属正常。

**字幕组列表里没有我想要的组**
字幕组来自真实搜索结果，只有这部番在该站点被该组发布过才会出现。可以先在资源列表里看看该组的命名，或把「限定字幕组」留空。

**下载的文件放在哪**
`<下载根目录>\<简体名>\`，可以在订阅页点「打开目录」直接跳转。qBittorrent 里分类为 `Bangumi`。

**想改端口 / 让局域网其他设备访问**
设置页可改端口，并勾选「允许局域网访问」（监听 `0.0.0.0`）。

### 实测结论（本机环境）

- Bangumi：token 校验通过，读取到 36 部「在看」，含视觉图与多语言别名
- 三站点：动漫花园 / 爱恋动漫 / Nyaa 均能搜索并解析出字幕组、分辨率、大小、做种、磁力
- 字幕组：动漫花园原生 `team_id` 精确过滤；跨站字幕组按「繁简转换 + 后缀归一 + 前缀相似」匹配
  （如「天月動漫&發佈組」与「天月动漫」视为同一组）
- qBittorrent：添加的任务分类为 `Bangumi`、标签为 `自动追番`、保存路径为 `<下载根目录>\<简体名>`
- UI：真实 Chrome 测量下，表格每列左边缘与数字列右边缘偏差均为 0px，行高一致，无横向溢出

### UI 规范（改样式时请遵守）

| 项目 | 取值 |
|---|---|
| 控件高度 | 输入框 / 下拉 / 面板按钮统一 **40px**；表格行内按钮 32px；大按钮 46px |
| 圆角 | 控件 10px、卡片与面板 16px、弹窗 22px、胶囊（badge/chip/文件夹）999px |
| 表单栅格 | `.form-grid`（2 列）+ `.form-cell`（label 20px / 控件 / 提示），行间距 20px、标签到控件 12px |
| 字号 | 面板标题 15px、控件与按钮 13.5px、表单 label 12px、提示 11.5px |
| 数字对齐 | 一律 `class="num"`（等宽数字 + 右对齐） |
| 主题 | 三态：`html[data-theme]` 为生效主题，`html[data-theme-mode]` 为用户模式（auto/dark/light），两套颜色变量必须一一对应 |
| 下拉框 | 由 `app/web/ui.js` 自绘（原生弹层无法设圆角）；原生 `select` 仍留在 DOM 作真值来源，新增 select 会被自动接管 |

> 注意 1：写输入框选择器时用 `input:not([type="checkbox"])...` 而不是 `input[type="text"]` ——
> 没有 `type` 属性的 `<input>` 匹配不到属性选择器，会导致同表单里控件高度不一致（踩过这个坑）。
>
> 注意 2：自绘下拉**不要**按可见性做接管门槛。曾经的实现是「隐藏视图里的 select 不接管，
> 靠重试等它出现」，结果是用户十秒后才打开弹窗时，里面的下拉又变回原生样式（已修：隐藏也先建好）。
>
> 注意 3：`select.value = x` 不会触发 `change`，自绘文案会停在旧值。用 app.js 的 `setSelectValue()`
> 而不是直接赋值。
>
> 注意 4：`/api/search` 的缓存键包含「是否限定字幕组」。限定字幕组与不限定是两份不同的缓存，
> 否则限定某组时会命中全量缓存、显示别的组的资源（踩过这个坑）。
> 手动搜索关键词同样进缓存键（`...|kw=<词>`），不同关键词互不串味。
>
> 注意 5：**改默认值不等于生效**。`config.load()` 是 `_deep_merge(DEFAULT_CONFIG, raw)`，
> 已存在的持久化值会覆盖新默认值 —— 所以把默认从 true 改成 false 对老机器无效。
> 这类「行为性默认值」的变更必须走 `config._migrate()` 迁移（按 `version` 号一次性纠正），
> 例：`qbittorrent.create_subfolder` 从 true 改 false 就是这样落地的。
>
> 注意 6：**改了资源解析/识别规则，要同时让旧搜索缓存失效**。搜索缓存是「上一版程序」算好的结果，
> 直接复用会让用户一直看到旧字段（踩过：新增「字幕语言」后旧 payload 里没有 `lang`，
> 界面上全显示「未标注」；修好 Nyaa 解析后缓存里又缺 Nyaa 结果）。
> 现在 `warmup.SEARCH_SCHEMA` 是「解析相关源码的内容指纹」，改了 `sources/*.py`、`core/util.py`、
> `core/htmlx.py` 就自动作废重搜；读缓存时还会用 `base.normalize_items()` 重算一遍派生字段兜底。
>
> 注意 7：`engine.search_by_subject()` 统一用 `adapter.search(kw, group=…, page=…, lang=…)` 调站点，
> **每个适配器的 `search()` 都必须能接住这些关键字参数**。曾经 `NyaaAdapter.search()` 少了 `lang`，
> `TypeError` 被上层吞掉 → Nyaa 整站静默返回空结果，界面上只写一句「失败」。
> `_probe/t_lang.py` 第 7 节会用 `inspect.signature().bind()` 检查每个站点的签名。
>
> 注意 8：站点限流（HTTP 429）不能秒级重试。爱恋动漫在大批量预热时会返回 429，
> 现在按 `Retry-After` 退避（没有该头就等 3s×次数），并给该站点记 60 秒冷却，
> 冷却期内直接快速失败（报错写清楚还剩多少秒），不会把重试风暴打进站点。
>
> 注意 9：`htmlx.Node.text` 必须**按文档顺序**拼接文本（文本与子元素交错）。
> 以前的实现是「本节点所有文本 + 子节点文本」，于是动漫花园把命中关键词用
> `<span class="keyword">` 包起来时，标题会被拼成「[组] ！/ 其它名 - 14**关键词**」——
> 关键词跑到末尾、中段少一块（用户一眼就能看出标题不对）。回归：`_probe/t_htmlx_order.py`。
>
> 注意 10：**订阅选了字幕组，自动追番就必须真的只用这个组**。站点搜索是模糊匹配，
> 搜「[ANi] 番名」时 Nyaa 会把 AnoZu / ToonsHub / SubsPlease 等组的结果一起带回来；
> 早期版本只在**搜索词**里带组名、**候选列表完全不过滤**，于是选 ANi 却下到了 [AnoZu] 的第 3 集
> （用户报的）。现在 `watcher._new_candidates` 会用 `engine._group_match()` 再核对一次。
> 同时修掉了组名匹配的误判：旧规则拿「较短名字的前 2 个字符」做包含判断，
> `ani`[:2] = `an` 正好出现在 `anozu` 里 → 两个不同的组被判成同一个。现在 ASCII 名之间
> 只认「相等 / 去后缀相等 / ≥4 字符的包含」，前缀相似只对中日文名生效。
> 回归：`tests/test_engine.py::TestNewCandidates::test_group_filter_only_keeps_chosen_group`。
>
> 注意 11：**qBittorrent 没开时，下载失败的资源必须存下来**（用户报：番剧更新时 qB 没开，
> 之后再打开也不会补）。为什么不能只靠「下一轮重新搜」：
> ① 站点搜索结果按做种数/时间排，几小时后同一集可能已经掉出第一页，搜不回来就永远补不上；
> ② 追番每 30 分钟才跑一轮，用户开着 qB 也要等半小时；
> ③ 站点抖动时（dmhy 500 / SSL 超时）那一轮连搜索结果都拿不到，更别说下载。
> 现在 `watcher.check_subscription` 下载失败就把资源（**含 magnet**）写进 `data/pending.json`
> （`app/core/pending.py`，原子写、去重、上限 200 条、7 天过期），
> 后台巡检线程 `anime-pending` 每 `queue.retry_seconds`（默认 60 秒）探一次 qBittorrent，
> 连上了就按加入顺序补下载（每次最多 `queue.max_per_flush` 条），成功一条删一条；
> 每轮追番开始时也会顺手补一次。界面：侧栏 `待下载 N 集`（点一下手动重试）、
> 订阅卡片提示、汇总条「立即补下载」按钮，补完自动消失并提示「已补下载 N 集」。
> 回归：`tests/test_pending.py`（14 例）、`_probe/t_queue.py`（端到端 21 项）。
